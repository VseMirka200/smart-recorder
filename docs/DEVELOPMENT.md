# Разработка Smart Recorder

Этот документ описывает локальную разработку, проверку и сборку проекта.

## Требования

Рекомендуемая среда:

- Windows 10 или Windows 11;
- AutoHotkey v2 для запуска исходного `.ahk`;
- PowerShell для штатной сборки;
- Git для работы с репозиторием.

## Основной код

Главная точка входа:

```text
SmartRecorder.ahk
```

В одном скрипте находятся:

- GUI настроек;
- горячие клавиши;
- запись действий;
- воспроизведение;
- работа с профилем;
- OCR-сценарии;
- сохранение и загрузка записей;
- журнал и панель состояния.

Подробное описание структуры находится в [`ARCHITECTURE.md`](ARCHITECTURE.md).

## Запуск из исходников

1. Установите AutoHotkey v2.
2. При необходимости получите `OCR.ahk` через `Install_OCR.bat` или сборочный скрипт.
3. Запустите `SmartRecorder.ahk`.

## Сборка EXE

Самый простой способ:

```bat
BUILD_EXE.bat
```

Этот файл запускает `BUILD_EXE.ps1`, который:

1. проверяет необходимые файлы;
2. подготавливает каталог `.buildtools`;
3. загружает закреплённую версию AutoHotkey при необходимости;
4. проверяет SHA256 архива AutoHotkey;
5. получает Ahk2Exe, если компилятор отсутствует;
6. восстанавливает OCR-зависимость при необходимости;
7. собирает `SmartRecorder.exe`;
8. применяет `SmartRecorder.ico` к EXE.

## Runtime-данные

Программа может создавать локальные данные:

```text
recordings/
screenshots/
```

Они не должны попадать в репозиторий, если только это не специально подготовленные обезличенные тестовые данные.

## Проверка изменений

Минимальный smoke-test перед коммитом:

1. Программа запускается без ошибок.
2. Окно настроек открывается и не содержит обрезанного текста.
3. F8 начинает и завершает запись.
4. F9 запускает воспроизведение.
5. F10 немедленно останавливает воспроизведение.
6. F11/F12 корректно показывают и скрывают панели.
7. Новый профиль генерируется в заданном диапазоне.
8. Сохранённая запись загружается после перезапуска.
9. Если изменялся OCR, отдельно проверены успешный сценарий и отсутствие OCR-зависимости.
10. Если изменялся F4, проверены снимки и поведение у краёв экрана.

## GUI

При изменении интерфейса:

- сохраняйте одинаковые горизонтальные и вертикальные отступы;
- проверяйте длинные русские подписи;
- не размещайте элементы вплотную к границе GroupBox;
- избегайте разных ширин одинаковых по смыслу полей;
- проверяйте стандартный масштаб Windows и, по возможности, 125–150%;
- не увеличивайте окно без необходимости.

## OCR

OCR является отдельной зависимостью и может отсутствовать в локальной копии. Код должен корректно обрабатывать это состояние и не завершать приложение аварийно.

Не добавляйте скачанный `OCR.ahk` в Git, если политика `.gitignore` остаётся неизменной.

## Диагностика

При сложной ошибке полезно проверить:

- журнал действий;
- состояние глобальных флагов записи/воспроизведения;
- координатный режим мыши и пикселей;
- текущий путь записи;
- доступность OCR;
- состояние клавиш, удерживаемых во время воспроизведения.
