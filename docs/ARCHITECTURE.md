# Архитектура Smart Recorder

Smart Recorder — монолитное приложение на AutoHotkey v2. Большая часть поведения сосредоточена в `SmartRecorder.ahk`, а внешние файлы используются для сборки, иконки и необязательной OCR-зависимости.

## Основные части

### 1. Инициализация

При запуске скрипт:

- настраивает координатные режимы мыши и пикселей;
- инициализирует глобальные настройки и состояние;
- проверяет доступность OCR;
- применяет иконку приложения;
- создаёт окна статуса, журнала и настроек;
- загружает последнюю сохранённую запись, если она существует.

### 2. GUI

Приложение использует несколько окон:

- окно настроек — основные параметры запуска, тайминги и профиль;
- панель состояния — информация о текущем режиме;
- журнал — последние действия и диагностические сообщения.

GUI напрямую связан с глобальными настройками, которые применяются перед запуском записи или воспроизведения.

### 3. Горячие клавиши

F1–F12 и Esc являются основным быстрым интерфейсом программы. Обработчики горячих клавиш вызывают отдельные функции, которые работают с текущим состоянием приложения.

Подробный список находится в `docs/HOTKEYS.md`.

### 4. Запись

Подсистема записи хранит последовательность событий во внутреннем массиве. Для событий учитываются время, действия мыши и клавиатуры, а также служебные события приложения.

Ключевые состояния:

- идёт ли запись;
- момент начала записи;
- последняя позиция мыши;
- счётчики действий;
- необходимость временно игнорировать захват событий программы.

### 5. Воспроизведение

Воспроизведение выполняет сохранённые события с учётом:

- выбранной скорости;
- количества повторов;
- случайного кулдауна;
- сигнала немедленной остановки;
- состояния удерживаемых клавиш.

Перед полным запуском программа может заранее рассчитать план кулдаунов для отображения ожидаемого времени выполнения.

### 6. Тестовый профиль

Профиль содержит возраст и пол. Возраст генерируется в заданном диапазоне, а режим пола выбирается пользователем или случайным образом.

Профиль может обновляться перед каждым повтором.

### 7. OCR

OCR используется только в сценариях, где требуется распознавание содержимого интерфейса. Зависимость может отсутствовать, поэтому приложение сначала проверяет её доступность и должно продолжать работать без аварийного завершения.

OCR-логика отделена от обычной записи/воспроизведения настолько, насколько это возможно в рамках одного скрипта.

### 8. Снимки

Для сценариев, связанных с F4, используется отдельный каталог снимков. При вычислении области необходимо учитывать границы экрана и многомониторные конфигурации.

### 9. Хранение записей

Рабочая запись по умолчанию хранится в:

```text
recordings/last_recording.srm
```

Путь к текущей записи хранится отдельно, поэтому пользователь может загрузить другой файл.

Runtime-данные не предназначены для коммита в Git.

## Сборка

`BUILD_EXE.bat` является простой точкой входа для пользователя.

`BUILD_EXE.ps1` отвечает за подготовку инструментария и компиляцию:

```text
SmartRecorder.ahk
      │
      ├── OCR.ahk (при наличии/необходимости)
      ├── SmartRecorder.ico
      │
      ▼
    Ahk2Exe
      │
      ▼
SmartRecorder.exe
```

## Направление рефакторинга

Если приложение продолжит расти, логично постепенно разделить монолитный скрипт на модули:

```text
src/
  Gui.ahk
  Recorder.ahk
  Playback.ahk
  Profile.ahk
  OcrHelper.ahk
  Storage.ahk
```

Такой переход стоит выполнять постепенно, сохраняя работоспособность после каждого шага.
